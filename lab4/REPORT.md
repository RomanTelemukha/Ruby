class Point
  attr_reader :x, :y

  def initialize(x, y)
    @x = x
    @y = y
  end

  def +(other)
    Point.new(@x + other.x, @y + other.y)
  end

    @x == other.x && @y == other.y
  end

    @title = title
    @price = price
  end

  def price
    @price
  end

  end

  def title
    @title
  end

### Висновки
Під час виконання лабораторної роботи було опановано синтаксис та різновиди методів у мові Ruby:
1. Засвоєно механізм аргументів за замовчуванням та перевизначення методів у таблиці методів Ruby.
2. Реалізовано іменовані необов'язкові параметри (keyword arguments), логічні предикатні методи (із суфіксом `?`), операторні методи (`+`, `==`) та методи присвоювання (сетери).
3. Розглянуто передачу масивів у методи за допомогою звичайних аргументів та splat-оператора `*`.
4. Опановано роботу з блоками через ключове слово `yield` (з перевіркою `block_given?`) та явні блок-параметри `&block` із методом `.call`.
5. Практично досліджено фундаментальні відмінності між `Proc` та `Lambda`: неконтрольованість арності аргументів у `Proc` проти суворої перевірки в `Lambda`, а також поведінку оператора `return` (в `Proc` виходить з усього охоплюючого методу, а в `Lambda` повертає значення локально та дозволяє методу продовжити виконання).

### Відповіді на контрольні питання

1. **Як у мові Ruby реалізується перевизначення методів, і що відбувається зі старим кодом методу при оголошенні нового з такою ж назвою?**  
   При повторному оголошенні методу з тим самим ім'ям у тому ж контексті новий метод перезаписує старий запис у таблиці методів класу/модуля. Старий код стає недоступним за цим ім'ям (якщо не був створений аліас або не використовується `super` у підкласі).

2. **Яким чином працюють аргументи за замовчуванням у методах Ruby, і в якому порядку вони обчислюються під час виклику?**  
   Аргументи за замовчуванням оголошуються через знак `=` (наприклад, `param = default_value`). Вони обчислюються зліва направо у момент виклику методу, тому один аргумент може посилатися на попередній.

3. **У чому полягає відмінність між звичайними позиційними аргументами та іменованими параметрами?**  
   Позиційні аргументи зіставляються за їхнім порядком передачі. Іменовані параметри (`key: value`) зіставляються за іменами ключів незалежно від порядку передачі, що робить код більш читабельним та самодокументованим.

4. **Що таке предикатні методи в Ruby, яка синтаксична традиція їх найменування та що вони повинні повертати?**  
   Предикатні методи — це методи, які перевіряють певну умову. За конвенцією Ruby їхнє ім'я закінчується знаком питання `?` (наприклад, `even?`, `empty?`), і вони повертають логічне значення `true` або `false`.

5. **Як перевантажити або створити власний метод-оператор (наприклад, +, *, ==) для кастомного класу в Ruby?**  
   Більшість операторів у Ruby є звичайними методами. Їх можна визначити у класі за допомогою стандартного синтаксису: `def +(other) ... end` або `def ==(other) ... end`.

6. **Який синтаксис використовується для створення методів присвоювання і як вони викликаються в коді?**  
   Метод присвоювання створюється за допомогою додавання знака `=` до імені методу: `def price=(val) ... end`. Викликається він як звичайне присвоювання: `object.price = 100`.

7. **Як передати масив у якості аргументу методу, і в чому полягає відмінність між викликом def foo(arr) та синтаксисом «splat-оператора» def foo(*args)?**  
   У `def foo(arr)` метод очікує рівно один аргумент — об'єкт масиву. Синтаксис `def foo(*args)` збирає довільну кількість переданих аргументів у внутрішній масив `args`. При виклику `foo(*my_arr)` splat розпаковує масив на окремі аргументи.

8. **Яким чином методу передається блок коду як явно вказаний аргумент і за допомогою якого методу цей блок запускається на виконання?**  
   Блок передається як останній параметр методу з префіксом амперсанда: `def foo(&block)`. Запускається він методом `.call`, наприклад `block.call` або `block.call(arg)`.

9. **Як працює ключове слово yield без аргументів і з аргументами у контексті передачі управління з методу в блок?**  
   `yield` передає керування з тіла методу у переданий блок. Без аргументів (`yield`) викликає блок без параметрів; з аргументами (`yield(a, b)`) передає вказані значення у блок як параметри `|a, b|`.

10. **Як убезпечити метод із yield від виклику без блоку?**  
    Використовувати вбудований предикат `block_given?`, наприклад: `yield if block_given?`.

11. **У чому виражається «неконтрольованість» аргументів в об'єктах Proc при передачі більшої або меншої кількості параметрів, ніж оголошено?**  
    `Proc` має нестрогу перевірку арності: якщо передати менше аргументів, відсутні ініціалізуються значенням `nil`; якщо передати більше — зайві аргументи просто ігноруються, помилка `ArgumentError` не виникає.

12. **Як поводиться оператор return всередині об'єкта Proc, якщо його викликано всередині іншого методу?**  
    Оператор `return` всередині `Proc` здійснює вихід не лише з самого блоку, а з усього методу, в якому цей `Proc` був створений або викликаний.

13. **У чому полягає суворість («контрольованість») Lambda щодо кількості переданих аргументів у порівнянні з Proc?**  
    `Lambda` суворо контролює кількість переданих параметрів, як і звичайний метод: якщо кількість переданих аргументів не збігається з оголошеною, генерується виняток `ArgumentError`.

14. **Як поводиться оператор return у Lambda при її виконанні всередині іншого методу, і чим ця поведінка фундаментально відрізняється від Proc?**  
    Оператор `return` у `Lambda` повертає значення тільки з самої лямбди, після чого виконання охоплюючого методу продовжується далі (на відміну від `Proc`, який повністю перериває весь метод).
